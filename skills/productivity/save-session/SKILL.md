把本次会话沉淀成一份**可复现、可复习**的文档集，放在 `~/md/` 下。

> `~/md` 可能是软链（本机指向 Obsidian 库）。写入前先 `readlink -f ~/md` 确认真实位置。

## 顶层单元

- 一次会话 = 一个顶层目录，命名 `YYYY-MM-DD-<slug>`（英文短横线，能概括主题）。
- **多主题**：若本次会话涉及多个彼此独立的主题，可以按需分配**多个顶层目录**来工作，每个主题一个。
- **拆分判据**（避免碎片化）：两个主题**没有共享的验证步骤、也没有因果依赖**时，才拆成独立顶层目录；否则放在同一目录下的多份文档。
- 目录名用**本地日期**；在根 README 注明时区（如 `CST/UTC+8`）。

## 目录约定（按角色，不绑定任何固定名字）

```
<会话目录>/
├── README.md   唯一入口：问题→答案速查表、总体架构、探索过程（现象→排查→根因→修复→验证）
├── docs/       主题文档，一个主题一个文件
└── code/       代码/脚本/配置；由 code/README.md 索引（文件→用途→目标机→怎么跑）
```

- **docs 文件名**：`<主题>-<类型>.md`，类型取
  `qa` 问答 · `troubleshooting` 排障 · `lab` 可复现实验 · `playbook` 可迁移方法论 · `architecture` 架构与机制 · `memo` 可持续追加的备忘
- **每份文档统一小节**：`现象 → 观察（命令 + 输出 + 结论）→ 根因 → 修复 → 验证`；能复现的一律写成 `Lab`（最小场景 + 期望输出 + 验收判据）。
- **双向可追溯，禁止孤儿**：文档里的代码片段必须指到具体 `code/` 文件；`code/README.md` 里每个文件写明「用途 / 目标机 / 怎么跑」。
- 文档之间、文档与 `code/` 之间互相链接；根 README 指到各文档。

## 每份 docs 的头部（YAML frontmatter，仍是 Markdown）

Obsidian 会把它渲染成顶部的 Properties 面板（不是正文原文）；纯文本视图里就是这 4 行：

```yaml
---
topic: 主题名
kind: lab                 # qa | troubleshooting | lab | playbook | architecture | memo
status: 已落地             # 已落地 | 计划中
verified_at: 2026-10-07   # status=已落地 时必填
---
```

- `kind` 必须与文件名后缀一致。
- 已有文档**不回填**，只对新文档生效。

## 内容清单（尽量给足细节）

1. 问题与答案
2. 探索过程（含失败的尝试）
3. 经验教训
4. 用到的工具与命令
5. 用户可带走的**知识**与**技能**
6. **第一性原理视角**：这个问题从根本原理上应该怎么做
7. 背景知识
8. 最小复现场景
9. 可重复练习的小测验 + 验收标准
10. 权威信息获取途径
11. 用 **Mermaid** 画的模块/知识关联图

## 代码

- 代码、脚本、配置**一律放 `code/`**；正文只留关键片段并指到 `code/`。
- 长脚本单独成文件；`code/README.md` 必须写明每个文件干什么、属于哪台机器、怎么执行。

## 写作硬规则

- **命令必须实跑过**：文档里出现的每条命令都必须在机器上执行过；引用的脚本必须真实存在（先 `ls` 确认）。
- **来源不是记忆**：结论要给出处（源码行号 / 官方原文 / 实测输出）。没有实测输出的判断标 `（推测，未验证）`。
- **证据而非叙事**：观察写成 `命令 → 输出 → 结论`；只贴与判据相关的行，完整输出另存文件。
- **状态分开**：每条结论标 `已落地（验证于 <日期>）` 或 `计划中（未验证）`。
- **可重跑性**：命令标注 `可重跑` / `一次性`；`一次性` 必须附回滚步骤。
- **脱敏**：凭据、私钥、token 一律写成 `<redacted>`，绝不入档；内网 IP / 主机名可保留但标注「内网」。
- **30 秒入口**：根 README 第一屏必须回答「这是什么 + 结论是什么 + 下一步做什么」。

## 收尾自检（这些判据必须能失败）

- 根 README 有「问题→答案速查表」，且第一屏能读懂？
- `docs/` 每份都有 `现象 → … → 验证` 小节，且 frontmatter 的 `kind` 与文件名后缀一致？
- 每个 `code/` 文件都能在 `code/README.md` 里找到「用途 / 目标机 / 怎么跑」？反向查：有孤儿文件吗？
- 每条 `已落地` 的结论，都能指出对应的验收判据（命令或观察）？
- 有没有未脱敏的敏感信息？`grep -riE 'BEGIN .*PRIVATE KEY|hmac|token|password' .` 应为空或只命中 `<redacted>`。
